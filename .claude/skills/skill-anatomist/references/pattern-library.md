# 模式库：已知的成功模式与失败模式

从已分析的 Skills 中提炼。分析新 skill 时，与本库匹配以识别已知模式。

本库持续更新。每次分析新 skill 时，如发现新模式应追加到对应章节。

---

## 成功模式

### 结构类

#### 步骤化工作流（Stepwise Workflow）
- **频率**：5/6
- **特征**：编号步骤 + checklist + 阻塞标记
- **为什么有效**：将认知负担从"理解全局"降为"只看当前步骤"。checklist 给用户掌控感。阻塞标记防止跳步导致的错误。
- **典型实现**：baoyu-cover-image 的 6 步 + ⛔ BLOCKING 标记
- **质量分层**：
  - 标准：有编号步骤
  - 优秀：步骤间有依赖标记
  - 创新：带可视化流程图（如 ASCII 流程）

#### 多维参数矩阵（Multi-Dimension Parameter Matrix）
- **频率**：3/6
- **特征**：多个独立维度，每个维度有限选项，自由组合
- **为什么有效**：把"从零创造"变成"选择组合"。每个维度独立决策，降低组合复杂度。
- **典型实现**：baoyu-cover-image 的 5 维（Type × Palette × Rendering × Text × Mood）
- **质量分层**：
  - 标准：有维度但无推荐
  - 优秀：有 auto-selection 规则
  - 创新：维度间有兼容性矩阵

#### 渐进式披露（Progressive Disclosure）
- **频率**：4/6
- **特征**：元数据 → 主体 → 引用文档，分层加载
- **为什么有效**：避免信息轰炸。用户按需深入，不需要一次消化全部内容。
- **典型实现**：skill-creator 的三层（Metadata → SKILL.md → Bundled resources）
- **质量分层**：
  - 标准：有引用文档
  - 优秀：主体中有明确指针告诉何时读哪个引用
  - 创新：分层与用户角色匹配（新手看层1，高级看层3）

#### 自动默认 + 手动覆盖（Auto-Defaults with Override）
- **频率**：4/6
- **特征**：所有参数有合理默认值，用户可按需覆盖
- **为什么有效**：兼顾新手（零配置开始）和老手（完全可控）。降低首次使用的决策成本。
- **典型实现**：baoyu-cover-image 的 auto-selection + --quick 模式
- **质量分层**：
  - 标准：有默认值
  - 优秀：有 --quick 或极简模式
  - 创新：默认值基于内容分析动态推荐

#### 输出文件结构规范（Output File Spec）
- **频率**：4/6
- **特征**：明确的目录结构、命名规则、冲突处理
- **为什么有效**：输出可预测 → 可自动化 → 可追溯。kebab-case slug + 时间戳冲突处理是成熟子模式。
- **典型实现**：baoyu-cover-image 的 `cover-image/{slug}/` 结构
- **质量分层**：
  - 标准：有输出路径说明
  - 优秀：有命名规范 + 冲突处理
  - 创新：输出结构支持版本追溯

### 价值类

#### 反模式清单（Anti-Pattern Listing）
- **频率**：3/6
- **特征**：Do / Don't 对照表，NEVER 清单
- **为什么有效**：比正面指导更令人印象深刻。"不要这样做"比"应该那样做"的行为改变力更强。
- **典型实现**：frontend-design 的"NEVER use Inter/Roboto/Arial"
- **质量分层**：
  - 标准：列出不该做什么
  - 优秀：Do/Don't 成对出现
  - 创新：反模式配真实案例截图或代码

#### 完成报告（Completion Report）
- **频率**：3/6
- **特征**：任务完成后输出结构化摘要
- **为什么有效**：给用户"完成了"的明确信号。包含关键参数方便回溯。文件列表让输出透明。
- **典型实现**：baoyu-cover-image 的 "Cover Generated!" 报告
- **质量分层**：
  - 标准：有完成提示
  - 优秀：包含参数摘要 + 文件列表
  - 创新：包含对比（优化前 vs 优化后）

### 心理类

#### 焦虑→确定性管道（Anxiety → Certainty Pipeline）
- **频率**：5/6
- **特征**：识别用户焦虑，通过框架/流程/清单转化为确定性
- **为什么有效**：命中用户的情感痛点。焦虑越精准，skill 越有"磁力"。确定性是最强的使用动机。
- **典型实现**：
  - "我不会设计封面" → 5 维参数选择（cover-image）
  - "我不知道怎么写 Skill" → 迭代循环方法论（skill-creator）
- **识别技巧**：想象用户在使用 skill 前的内心独白

#### 赋能叙事（Empowerment Narrative）
- **频率**：4/6
- **特征**：让用户感觉"我变强了"而非"我依赖了工具"
- **为什么有效**：长期留存。用户不只是完成任务，还获得了新的认知框架。
- **典型实现**：frontend-design 的 "Don't hold back, show what can truly be created"
- **识别技巧**：检查 skill 是否教用户"为什么"而不只是"怎么做"

## 失败模式

### 信息过载（Information Overload）
- **频率**：2/6
- **特征**：> 300 行无分层，一次性倒出所有信息
- **后果**：用户不读或只读开头，后半部分浪费
- **修复**：渐进式披露 + Quick Start + 按需引用

### 关键外部依赖（Critical External Dependency）
- **频率**：1/6
- **特征**：核心价值完全依赖外部 URL / API / 工具
- **后果**：外部不可用 → skill 失效
- **修复**：本地缓存 + fallback + 至少内联核心摘要

### 有规则无示例（Guideline Without Examples）
- **频率**：2/6
- **特征**：抽象规则但无具体 before/after
- **后果**：用户理解规则但不知道如何应用
- **修复**：每条关键规则配 1 个具体示例

### 环境假设（Environment Assumption）
- **频率**：1/6
- **特征**：假设特定工具 / 环境 / 权限可用
- **后果**：换个环境就跑不通
- **修复**：检测环境 + 多环境适配 + 明确前置条件

## 模式组合规律

高分 skill 通常包含以下组合之一：

| 组合名 | 要素 | 适合场景 |
|--------|------|---------|
| **工作流型** | 步骤化 + 自动默认 + 完成报告 + 焦虑管道 | 生成任务、自动化流程 |
| **知识库型** | 渐进披露 + 反模式清单 + 多维参数 + 赋能叙事 | 设计系统、最佳实践 |
| **元技能型** | 步骤化 + 迭代循环 + 评估体系 + 赋能叙事 | 教用户创建/改进某类事物 |
| **哲学型** | 反模式清单 + 赋能叙事 + 思考框架 | 创意指导、审美方向 |
